# What I Did: Problem 3 — Bipedal Walker 범프 코스 거리 최대화

## Task

Bipedal Walker가 50개 장애물이 있는 범프 챌린지 코스에서 20초(1000스텝) 동안 최대한 먼 거리를 이동하도록 PPO 정책을 개선하는 과제. Baseline 모델(2.6M 스텝, v9)은 31.77m 도달. 목표는 낙상 없이 60m 이상.

## 병목 진단

`diag_run.py`로 트레이스를 분석한 결과:

- x=0~25m: 2.7~3.5 m/s로 순조로운 주파
- **x≈26.4m (bump8, h=1.0m 계단): step 500~930, 8.6초 정체**
- x=28~31.8m: 돌파 후 3.3 m/s 재주행, 시간 종료

→ 평지 속도는 충분했다. 진짜 병목은 bump8 2단 계단(h=0.5m→1.0m) 등반 능력.

## 접근 방식: 병렬 2-Run 전략

서로 다른 가설을 동시에 검증하기 위해 2개 학습을 병렬로 실행했다.

### Run A — Speed Booster

속도에 집중한 보상 설계:
- 속도 목표 보상: 2.5 m/s 초과분에 비례 보상(계수 0.5, 상한 2.0)
- 범프 근처에서는 속도 인센티브 80% 감쇠하여 안전 확보

### Run B — Stall Buster

계단 등반에 집중한 보상 설계:
- healthy 게이트: 1초 정체 시 healthy 보상(=1.0)을 0으로 차단
- stall 종료 10초→5초로 단축 (실패 샘플 조기 종료)
- 계단 점프 보상: 임계값 완화, 보상 10→15
- 계단 높이 보상: 임계값 완화(1.05→0.9), 보상 15→20
- 약한 속도 보상(계수 0.3, 3.0 m/s 기준)

### 공통 변경

- MIN_TORSO_Z: 0.9→0.7 (평가 OOD 갭 해소)
- 전진 보상 계수: 60→80
- speed_gate: 1.0→3.0으로 확장
- 동적 페널티 스케일링: 속도↑ → 안정화 페널티↓

## Phase 1 결과

| 전략 | 최고 점수 | 낙상률 | 판정 |
|------|----------|--------|------|
| **Stall Buster (B)** | **57.10 m** | 42% | **승리** |
| Speed Booster (A) | 52.93 m | 38% | Ceiling 도달, 정체 |

두 전략 모두 42%/38%의 높은 낙상률을 보이며 점수가 진동했다. 속도 인센티브가 보행을 불안정하게 만들었기 때문.

## Phase 2: 안정화 시도

Run B 최고점(4.6M, 57.10m)에서 페널티 스케일링을 완화(0.8→0.5)하고 ent_coef를 0.02로 올려 안정화를 시도했다.

결과: 낙상률 42%→33%로 개선, 진동폭 32m→20m로 감소. 그러나 peak 57.10m를 재현하지 못했고 55.64m에 머물렀다.

## Phase 3-4: 마감 1시간 전 최종 돌파 시도

58m 확보된 체크포인트에서 speed push와 고탐색 stall(ent_coef=0.03)을 시도했으나, speed 모드는 보행을 다시 붕괴시켰고 고탐색 stall도 56m를 넘지 못했다.

## 최종 결과

```
31.77 m  →  57.10 m (+80%)
1.59 m/s  →  2.86 m/s (+80%)
```

## Lessons Learned

1. **속도만 올리는 보상은 불안정성을 초래한다.** speed 모드는 더 높은 순간 속도(3.1 m/s)를 냈지만 낙상률이 높아 ceiling이 더 낮았다.

2. **계단 등반은 속도보다 one-time bonus + stall 차단이 효과적이다.** healthy 게이트와 계단 보상 강화가 속도 인센티브보다 +4m 더 나은 결과를 냈다.

3. **동적 페널티 스케일링은 양날의 검이다.** 속도 진동을 용인하여 빠른 보행을 가능하게 했지만, 동시에 42% 낙상률의 불안정성을 유발했다.

4. **Phase 2 안정화는 peak보다 consistency를 개선했다.** 낙상률 -9%p, 진동폭 -12m. 향후 curriculum 접근(안정화 → 점진적 속도 상향)이 필요하다.

5. **병렬 학습 + score_monitor 자동화가 빠른 의사결정을 가능하게 했다.** 2개 전략을 동시에 평가하고 실시간으로 전략을 전환할 수 있었다.
